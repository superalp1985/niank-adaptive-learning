# V17收尾检查：保留增益的坐标系问题

2026-10-13。训练完成、原始记录审计通过之后发现，不能改写既有数据。

## 已证实的问题

预测器输出实际动作执行后的下一帧RGB，增益的每个下标因此属于
下一时刻身体朝向的复眼坐标系。

但是EyeMemory.feedback直接把这个增益加到尚处于当前时刻坐标系的
utility。下一次EyeMemory.features再根据身体旋转，对utility执行
roll(-shift)。新增增益因此多转了一次。

可复核的单扇区演示：

```python
memory = EyeMemory(1, "revisable")
memory.features(zero_rgb, zero_proprio, reset=True)
gain[0, 10] = 0.04  # 输出是下一帧第10格
memory.feedback(gain)
next_proprio[0, 2] = 2 / 128  # 身体转过一格
memory.features(zero_rgb, next_proprio, reset=False)
# utility峰值在第9格；新增证据正确位置应是下一帧第10格
```

这不是物体坐标泄漏，也不影响原始画面、真实动作、碰撞/受击记录或
固定保留组。它影响可修订机制将收益分配到哪个方位。原始记录审计验证
数据保存与指标一致，不能代替学习规则坐标系正确性检查。

## 解释修正

仍可报告“本轮实现最终落后于固定保留”，但不能据此断言正确对齐的
保留算法失败。两组都表现出视觉控制学习；可修订组尚不是一个正确隔离
机制的验证。这个错误和增益量级过小分别记录，不用一个问题掩盖另一个。

原始完整快照保留收尾检查前的报告；主分支本文件和修正版报告优先。
不改变V17训练源代码、配置、哈希、结果，不重跑已完成配置。
